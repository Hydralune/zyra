# Packages

Shared runtime packages are split by responsibility. M0 defined the initial boundaries; M2 and M3 have filled runtime workers, commands, skills, symbolic reasoning, evaluation, and integrations enough to exercise the main graph.

The remaining first-stage risk is depth, not naming. M4-M6 must turn the current memory and scheduler placeholders into real modules and keep moving mature upstream capabilities out of loose vendor-pool status into callable Zyra packages, apps, or runtime adapters.
