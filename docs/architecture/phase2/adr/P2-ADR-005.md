## Decision

Development validates the single `phase2_strongest_v1` composition. It does
not run a full mechanism-combination search or tune thresholds after seeing
sealed results. Validation proceeds in this order:

1. deterministic unit, property, and mutation tests;
2. read-only replay for schema and receipt calculation only;
3. local and isolated integration for commit, lease, artifact, verifier,
   restart, fault, and recovery;
4. minimal controlled provider/edge smoke for physical identity and causality;
5. two sealed cross-domain long runs.

Replay and fixtures cannot substitute for live semantic effect. A disabled
mechanism must fail, degrade, or create an explainable behavior difference.

## Hard gates

Hard gates include sealed completion, zero human intervention, at least 2,000
effective transitions per final run, exclusive canonical custody, invalid
proposal rejection, idempotency, zero false early exit, zero privacy or
permission violation, zero duplicate owner, zero parent-source runtime
dependency, validation-before-spend, no-policy-training, readiness, memory
continuity, symbolic safety, and complete real local/edge/cloud dispatch
causality.

Every metric declares:

- unit and direction;
- threshold;
- evidence unit and independent sample unit;
- hard or optimization classification;
- empty-sample semantics;
- requirement IDs;
- evidence-contract IDs.

Every hard gate uses `empty_sample_semantics=fail_closed`. Transition counts
inside one run do not inflate the independent sample count.

## Optimization gates

The frozen targets are at least 20% communication-delivery reduction, 15%
envelope-byte reduction, at least 0.90 evidence utilization, and 10% median
token or real-cost reduction where strictly comparable. Wall-time P95
regression is at most 10%, steady-state churn at most 1.25 times baseline,
stable-window oscillation is zero, and change adaptation targets at most ten
effective transitions.

A task failure cannot count as an efficiency improvement. If one suggested
optimization threshold is missed but a statistically credible Pareto
improvement exists across success, quality, cost, token, time, and recovery,
only the Phase 2 exit review may make one explicit exception. It may not
rewrite the frozen metric or reuse an earlier run ID.

## Diagnostic trigger

Targeted diagnosis begins only after verifier/artifact failure, a hard-gate
failure, a clear efficiency regression, topology oscillation, incorrect
pruning, operator over-expansion, or unreasonable placement. Receipts first
locate the responsible layer. The minimum failing input is rerun with one
layer changed; any fix gets a new mechanism version and run ID.
