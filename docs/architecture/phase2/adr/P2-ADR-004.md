# P2-ADR-004: Profile lifecycle, activation, degraded fallback, and rollback

- Status: Accepted and frozen
- Date: 2026-07-29
- Slice: P2-S00-02
- P2 base commit: `e207b46ca690171139a718b8b85d808cb5a79c1e`
- Digest manifest: `config/phase2/contract-digests.json`

## Decision

Policy profiles use five explicit lifecycle values:

- `baseline`: immutable comparison input;
- `default`: the currently selected production profile;
- `validation`: isolated candidate behavior that is not yet default;
- `diagnostic`: read-only calculation that cannot change canonical state;
- `retired`: non-selectable history retained for receipt replay.

The frozen Phase 1 deterministic baseline remains the default until
`phase2_strongest_v1` passes activation. The strongest profile is currently
`validation / blocked_pending_readiness`. This slice does not claim that any
new mechanism is ready.

## Activation

Strongest activation requires, at the same configuration digest:

1. all five required mechanisms have an `activation_ready`
   `MechanismEvidenceReadinessReport`;
2. every required status is `deterministic_ready`;
3. source-role, state-owner, activation, ADR, and digest registries validate;
4. no-policy-training, owner, symbolic safety, continuity, physical dispatch,
   cleanroom, and sealed-run hard gates pass;
5. rollback and mechanism-disable evidence remains valid.

`evidence_only` is diagnostic-only. `unavailable` selects the explicit Phase 1
baseline. Neither may influence graph, route, lease, permission, side effect,
or budget. Missing, conflicting, or tampered registries fail closed.

## Degraded fallback

Fallback is a visible mechanism result, not exception swallowing. It writes a
`phase2.mechanism_degraded` event with source mechanism, input/report digest,
failure class, fallback profile, causation, and downstream decision. A failed
continuity or safety gate cannot be hidden by baseline fallback; it enters
recovery or replan.

## Rollback

Rollback pins `phase1_deterministic_baseline` for new decisions. It does not
delete proposals, commits, dispatches, or outcomes from the prior profile.
Historical receipts remain replayable by their original mechanism and config
digests. Already committed external side effects are reconciled through their
existing owner rather than undone by a policy registry.

## Frozen gate changes

`config/phase2/activation-gates.yaml` contains a canonical frozen-gate digest.
A threshold or lifecycle change without a superseding ADR is invalid. A
legitimate revision records the old digest, a higher revision, the new digest,
and a checksum-bound superseding ADR.
