## Memory continuity evidence

`MemoryContinuityReceipt` proves behavior across checkpoint, compact/restore,
role or worker handoff, process restart, and requirement revision. It records
before/after memory and obligation digests, current requirement revision,
critical fact provenance/version/confidence, rejected or downgraded stale
memory, and the first downstream decision or tool call that actually used the
restored state.

The sealed gates are 100% critical-fact recall, 100% unresolved-obligation
retention, zero superseded-requirement execution, zero unprovenanced critical
retrieval, and zero restore-induced duplicate completed work. A continuity
failure enters recovery or replan; baseline fallback cannot hide it.

`MemoryFabric` and existing compact/retrieval owners retain state custody. The
receipt is evidence, not a second memory store.

## Mechanism or model-assisted to symbolic evidence

The evidence bundle separates proposal and symbolic planes:

```text
raw proposal or fixed pretrained observation
  -> constraint-by-constraint verdict
  -> repaired/projected delta or no-commit
  -> canonical commit/permission/lease
  -> execution, artifact, and verification outcome
```

Adversarial classes include cycle, missing endpoint/capability, privacy,
budget/fan-out/churn overflow, stale graph or environment revision, unavailable
capacity/lease, and false early exit. Unsafe commits and production projector
bypass must both be zero.

`proposal_signal_mode` is `deterministic_only`,
`pretrained_model_assisted`, or `mixed`. Materials may say “neural-symbolic”
only when a real fixed pretrained model/embedding input, version, output, and
confidence receipt exists. Otherwise the correct term is
“mechanism/semantic-symbolic.”

## Physical dispatch evidence

`PhysicalDispatchReceipt` is the evidence unit; a logical location label is
not sufficient. It links scheduler decision, alternatives and signals to a
pre-execution lease, physical attempt, actual call, artifact, and verifier.

- Local requires real host/process/terminal identity.
- Edge requires an independent process/container/VM/remote-node identity,
  isolation and failure boundary, network endpoint, and health evidence.
- Cloud requires provider/model/request identity, usage, tokens, real cost,
  and latency.

`SIMULATED_EDGE`, semantic-only backends, mock providers, and cloud-degraded
runs without credentials are failure or regression evidence, not successful
physical dispatch evidence. Sensitive/local-only payloads must never dispatch
to cloud.

Required condition lanes cover normal placement, privacy/local-only, local
load, edge latency or health degradation, edge disconnect, cloud unavailable,
and changed cost or latency limits. The physical location must actually change
or remain unchanged for an explicit safety reason.

## Causal and public evidence

Every receipt carries run/task identity, causation/correlation, immutable input
and config digests, artifact/event references, and verifier outcome. Public UI
projections consume these receipts and redact private payloads; they do not
reconstruct success from static demo data.
