# P2-ADR-001: Canonical owners and proposal-only mechanisms

- Status: Accepted and frozen
- Date: 2026-07-29
- Slice: P2-S00-02
- P2 base commit: `e207b46ca690171139a718b8b85d808cb5a79c1e`
- Digest manifest: `config/phase2/contract-digests.json`
- Supersession: a new ADR is required before any canonical owner or proposal boundary changes

## Decision

Phase 2 does not transfer an existing canonical owner. ARG-Designer, CARD,
AgentPrune, MaAS, and optional pretrained-model signals produce immutable,
versioned proposals or read-only features. They cannot mutate shared graph
objects, grant permission, consume execution budgets, allocate leases, dispatch
workers, or commit side effects.

The graph path is:

```text
immutable snapshot
  -> mechanism proposal
  -> symbolic projector
  -> GraphDeltaBuilder
  -> GraphStateCustody.commit
```

`GraphStateCustody` remains the only graph commit owner.
`DynamicTopologyRuntime` and `GraphDeltaBuilder` are authorized Zyra writers,
not alternate owners. `ResourceScheduler` retains physical placement and
execution-budget decisions. Existing permission, task/session, memory,
worker-lease, provider, artifact, and event owners remain authoritative.

LoopX owns only its private goal, todo, claim, history, and plugin state. A
LoopX claim is not a worker lease, and LoopX quota is not a Zyra execution
budget. The future bridge may correlate and project state, but may not create a
second writer for a Zyra domain.

## Enforcement

`config/phase2/state-owners.yaml` is a constraint overlay. It checksum-binds the
frozen first-stage owner evidence catalog instead of replacing it. The runtime
validator rejects:

- duplicate domains or additional canonical owners;
- ARG, CARD, AgentPrune, or MaAS as a canonical owner;
- MaAS ownership of placement, lease, or execution budget;
- LoopX ownership outside its private domain;
- a changed or missing frozen owner evidence catalog.

The registry is governance data only. It does not store graph, memory,
scheduler, lease, permission, task, event, or artifact state.

## Consequences

Mechanisms can be independently disabled, diagnosed, and rolled back without
changing state custody. A proposal can be rejected or repaired without
creating a canonical mutation. Any future owner transfer is high risk and must
define migration, compatibility, recovery, rollback, and affected tests in a
superseding ADR.
