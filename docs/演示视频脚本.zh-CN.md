## 1. 任务一：Web 工作台交互式长程任务

### 1.1 这一步演示什么

演示 ZYRA 的**生产任务图**：用户给一个自然语言目标，系统自动拆成 5 个阶段
（规划 → 选择执行资源 → 执行 → 验证 → 整理结果），由 CodeWorker 驱动模型多轮
工具调用（写文件、跑命令、修错），最终产出可检查的交付物与证据链。

### 1.2 启动（一个命令）

```bash
cd "C:/Users/Ylon/Desktop/挑战杯2026/zyra"
python scripts/dev_up.py
```

预期输出：

```
[dev_up] started zyra-api (pid ...)
[dev_up] waiting for API at http://127.0.0.1:8000 ...
[dev_up] started zyra-web (pid ...)
[dev_up] waiting for Web at http://127.0.0.1:5173 ...

Zyra is running:
  API   -> http://127.0.0.1:8000
  WebUI -> http://127.0.0.1:5173
Press Ctrl+C to stop both services.
```

### 1.3 录屏步骤

1. 浏览器打开 **http://127.0.0.1:5173**，停在工作台首页。
2. 在输入框粘贴下列目标（**本脚本固定用这条，保证可复现**）：

   ```
   在任务工作区创建 Python 模块 palindrome.py，实现 is_palindrome(s) 函数
   （忽略大小写与非字母数字字符）；创建 test_palindrome.py 单元测试；
   运行测试并报告结果。
   ```

3. 回车提交。**镜头跟随界面**，依次展示：
   - 左侧任务列表出现新任务，状态从「规划」开始推进；
   - 右侧步骤条走完 **5/5 阶段**（规划 → 选择执行资源 → 执行 → 验证 → 整理结果）；
   - 「执行」阶段停留最久——这是模型多轮工具调用的真实时间；
   - 最终状态 **已完成**，显示 **用时**、**交付物数量**。
4. 点开「查看完整证据链」，展示：
   - 最终回答（模型自述做了什么、验证命令、通过情况）；
   - 验证代码块（`python -m unittest -v test_palindrome` → `Ran 15 tests ... OK`）；
   - 事件轨迹（拓扑路由、资源决策、约束检查、工件写入）。

> **期望结果**：约 2–3 分钟完成，产出 `palindrome.py` 与 `test_palindrome.py`，
> 15/15 单元测试通过，WebUI 显示全部 5 个阶段完成。

### 1.4 旁白要点

- 「这不是聊天，是一条有状态的流水线：每个阶段都留下事件与证据。」
- 「代码是模型在受治理的工作区里真写的，测试是真跑的，通过与否由确定性验证器判定。」
- 「界面展示的是状态的投影，不是第二个事实来源。」

## 2. 任务二：Sealed 封存自治长程场景

### 2.1 这一步演示什么

演示 ZYRA 的**正式长程验证路径**：在**干净工作区**中，让完整系统（控制平面 +
资源调度 + 物理分派 + 故障注入 + 恢复）跑完两个跨域长任务，全程**零人工干预**，
并由独立验证器从原始事件重算状态迁移。

- **软件交付任务**（`live.software-delivery`）：在隔离工作区完成代码发现、规划、打补丁、
  git、测试、故障恢复、再验证与证据发布。
- **跨源研究任务**（`live.cross-source-research`）：从公开权威源（RFC / IANA / MDN）
  实时采集内容，做校验和绑定、断言抽取、引用核验与结构化交付。

### 2.2 准备（一次性）

Sealed 场景要求**初始状态干净**。工作台会把预检指向专属的场景暂存目录（不是正在运行
的产品库），因此**在同一个工作台里即可直接运行**，无需另开终端或 worktree。

若需从命令行跑正式封存套件（两个跨域 run、冻结 manifest），才需要独立 worktree：

```bash
cd "C:/Users/Ylon/Desktop/挑战杯2026/zyra"
git worktree add "C:/Users/Ylon/Desktop/挑战杯2026/zyra-sealed" HEAD
cd "C:/Users/Ylon/Desktop/挑战杯2026/zyra-sealed"
cp "../zyra/.env.deepseek.local" .env.deepseek.local
bun install --frozen-lockfile
python scripts/make_sealed_demo_manifest.py   # 冻结候选 commit 与受保护文件摘要
```

### 2.3 在 WebUI 上运行（推荐，全程点按钮）

1. 保持 `python scripts/dev_up.py` 已启动，浏览器打开 **http://127.0.0.1:5173**。
2. 首页下方「**长程任务演示**」面板有两个按钮：
   - **软件工程交付** → `live.software-delivery`
   - **跨源技术研究** → `live.cross-source-research`
3. 点击任一按钮，系统会以 **sealed（封存）模式**创建并启动运行。按钮旁的连接标签应显示
   **已连接**；运行开始后卡片显示状态与运行 ID。
4. 切到「设置 → 任务试运行」，选中刚创建的记录，查看「执行情况」与「验收检查」：
   - 状态 / 耗时 / 初始状态检查 / 新输入检查 / 人工干预次数；
   - 有效步骤、无效步骤、产物数、证据是否已验证；
   - 故障恢复数、执行层级（local/edge/cloud）、模型与服务能力、结果验证、执行位置验证。

> **期望结果**：约 20–60 秒完成，`phase=succeeded`，有效步骤 ≥ 2000，
> 证据「已验证」，人工干预 0。

### 2.4 可选：命令行跑完整封存套件

### 2.5 旁白要点

- 「两个任务都在同一个工作台里点按钮运行，不需要命令行。」
- 「整个流程对人工干预零容忍：需求变更、节点失效、网络中断都由系统自主消化。」
- 「这里的关键不是『跑完了』，而是**可被独立复核**——验证器从原始事件重算，
  不采信运行器自报的数字。」
- 「每一个交付都绑定工件摘要、验证回执与因果事件索引。」

## 5. 常见问题

- **端口被占**：`dev_up.py` 默认 8000/5173；命令行封存套件用独立端口段（8400+）。
- **Bun 找不到**：确保 `ZYRA_BUN_EXECUTABLE` 指向 `node_modules/.bin/bun.exe`。
- **模型凭据**：只从 `.env.deepseek.local` 读取；缺失时系统 fail-closed，不会静默降级。
- **面板显示「正在重连」**：等几秒让工作台连上场景服务；连接正常后按钮才可点击。
- **命令行封存要求证据目录干净**：重跑前删除 `docs/evidence/phase2/sealed/webui-demo-evidence/`。
