### 12.2 补丁本身的客观结论

当前容器内 16 行补丁不正确，focused test 的真实失败为：

```text
FAILED sympy/geometry/tests/test_point.py::test_point_rmul
AttributeError: 'Point2D' object has no attribute 'as_coeff_Mul'
```

恢复会话已正确诊断：

- `Expr._op_priority = 10.0`；
- `Point` 没有更高的 `_op_priority`；
- 仅增加 `Point.__rmul__` 不足以让 `Rational * Point` 和 `Symbol * Point` 分派到 Point；
- 已选择但没有执行的最小修复是给 `Point` 增加类属性 `_op_priority = 10.5`，保留 `Point.__rmul__`，不改 `Point.__mul__`。

因此本轮失败首先是算法补丁未完成，不得描述为“正确补丁仅因基础设施失败而未提交”。

### 12.3 运行时根因

已确认两个软件缺陷：

1. **验证状态机自相矛盾**：同一 semantic scope 在源码未改变时，门控正确禁止再次运行；但 progressive decision 仍返回 `nudge_verification`，持续提示模型重跑原测试。结果是模型在“不得重跑”和“必须重跑”之间反复检查，没有进入确定性的 repair-first 状态。
2. **shell 批次误报后台占用**：同一批次的第三个快速、前台、定界源码读取被 `active_background_shell_limit_reached` 拦截，尽管返回元数据明确显示 `active_background_count=0`。原因是 admission counter 把前两个前台 shell 也预先计入潜在后台槽位。

此外，7 次压缩虽保留了核心诊断，但旧压缩提示没有强制保存“精确测试范围、退出码、当前 changed-file 列表、已选但未执行的具体编辑、后台 job id”。最后一次压缩已经写明 `_op_priority = 10.5` 是下一动作，但发生在截止前约 90 秒，随后进入 closeout，无法再执行副作用。

### 12.4 已实施修复

已修改：

- `packages/runtime/claude-runtime/src/loop/progressive-execution-runtime.ts`
- `packages/runtime/claude-runtime/src/query-engine.ts`
- `packages/runtime/claude-runtime/test/runtime.test.ts`

新状态转换为：

```text
semantic test failed + repair bytes unchanged
    -> nudge_action（先修源码，不允许把重跑当进展）
committed business repair
    -> nudge_verification（重跑原失败 scope）
same scope passes with real exit code 0
    -> verification debt cleared / final delivery
```

具体变化：

- 新增 `verificationRepairRequired()`，用 priority failure 的 `lastObservedWorkspaceMutationCount` 与 `repairMutationCount` 判定是否必须先修复；
